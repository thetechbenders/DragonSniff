# DragonSniff v0.5.0 — Connect the dots

DragonSniff v0.5.0 adds optional read-only PrusaLink telemetry, release-grade container publishing, and a validated HTTPS deployment path for trusted LANs.

PrusaLink observations can now place printer state, bed temperature, bed target, source health, and freshness on the same evidence timeline as Dragon-family telemetry, without giving DragonSniff control over either the printer or the observed Dragon-family device.

This release also moves official container images to The TechBenders GHCR namespace, introduces automated stable and RC releases, hardens handling of malformed device-originated JSON, and documents the HTTPS topology validated against Brave's LAN download warning.

## Highlights

- **PrusaLink correlation:** an optional, read-only printer source that polls only `GET /api/v1/status` and records normalized `source_observation` records in the same authoritative sequence as Dragon-family evidence. It is disabled by default and pauses during SSE Churn. A bounded one-hour retention reserve keeps printer context available alongside the existing live baseline.
- **Release-grade containers:** public `v0.5.0`, `latest`, and immutable full-SHA images under `ghcr.io/thetechbenders/dragonsniff`, produced by a single release workflow that gates on the exact package version, the full test suite, a clean wheel install, and a smoke test of the immutable image before anything is tagged.
- **Trusted-LAN HTTPS:** a tested topology for clean evidence downloads. A locally trusted certificate is terminated in front of DragonSniff's loopback listener, with `Host` and `Origin` forwarded unchanged. See [LAN HTTPS validation](https://github.com/thetechbenders/DragonSniff/blob/v0.5.0/docs/lan-https-validation.md).
- **Evidence hardening:** device-originated JSON containing lone surrogates can no longer corrupt local structured surfaces. Raw response text is preserved unchanged as evidence; parsed data is withheld with a deterministic `parse_error`. This closes the known limitation carried in v0.4.0 (#33).
- **Validated on real hardware:** two eight-hour Long Haul Thermal captures against a DragonBreath device completed with correct run identity, correct lease-expiry fail-safe handling, and zero HTTP/JSON failures.

## Upgrading containers

Official images now live at `ghcr.io/thetechbenders/dragonsniff`.

The previous `ghcr.io/danielbrownjr/dragonsniff` package is legacy and frozen. It remains at its last published state and receives no further releases, including `latest`. Existing Portainer and Compose deployments should update their `image:` reference and redeploy with the same volume declaration so existing evidence is preserved.

For stable deployments, use either:

- `ghcr.io/thetechbenders/dragonsniff:v0.5.0`
- `ghcr.io/thetechbenders/dragonsniff:latest`

To pin exactly this build, use the immutable release image:

- `ghcr.io/thetechbenders/dragonsniff:sha-f030eeba9ce46273d72a49ecd9495ae1d3e2397d`

The published image is Linux/amd64.

## Safety and scope

DragonSniff remains a passive, read-only evidence tool. It does not control Dragon-family devices or Prusa printers and is not part of either system's control or safety loop.

DragonSniff itself still serves plain HTTP; HTTPS requires the documented reverse-proxy topology. Authentication and public or untrusted-network deployment remain unsupported.

`v0.5.0-rc.1` was tagged but never completed promotion or publication. `v0.5.0` supersedes it.
